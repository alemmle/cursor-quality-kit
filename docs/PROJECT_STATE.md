# Project state

## What this is

Central repository for the AI Code Constitution (version in `VERSION`) and the rules, skills, hooks, and reusable GitHub workflows that enforce it across repositories and AI tools.

## Status

- Constitution v1.10.0 (see `CHANGELOG.md`): markdown that states a fact about the repository stays true of the committed code (Article 16). A plan names blast radius and how the change is reversed; a larger radius or unclear rollback for production, stored data, or a trust boundary is a stop (Article 17). Both judged in `code-review`. The regression guard does not parse markdown or compute blast radius.
- Constitution v1.9.0 (see `CHANGELOG.md`): pull-request size ceiling is 80 files or 2500 changed lines. A plan step is still at most 5 files and one subsystem. The regression guard does not measure size; `diff-review.sh` does.
- Constitution v1.8.0 (see `CHANGELOG.md`): grammar of user-facing text. Languages in scope are the ones the repository names, or every language that already has user-facing strings. A change to that text includes a grammar check of the text as the user sees it. A count combined with words is checked at 0, 1, and 2 and for every other number category that language uses. Judged in `code-review`. The regression guard does not parse grammar.
- Constitution v1.7.0 (see `CHANGELOG.md`): coordinator and unattended-agent rules. Tool-local shared context is scratch until committed; parallel lanes follow `orchestrate-workers`; a subscription is not human approval; a coordinator is not the judgement reviewer of work it delegated. Cursor Project usage is the installed `cursor-project` skill; the human how-to stays in `docs/GROK-PLAYBOOK.md`. The regression guard does not scan shared-context files.
- Constitution v1.6.0 (see `CHANGELOG.md`): Article 9, parametric values. A literal is for a marked prototype or mock, or for a true program constant. A value that product will enrich, or that differs by deploy, lives in config, environment, or a table. Judged in `code-review`. The regression guard does not flag literals.
- Constitution v1.5.0 (see `CHANGELOG.md`): acceptance pipeline (`.ai/bin/accept.sh`, `.ai/bin/diff-review.sh`) and agent hooks (`.ai/bin/agent-hook.sh` for Cursor, Claude Code, Codex). Research behind it: `docs/RESEARCH.md`.

## Decisions

- 2026-10-04 - Stale markdown that names commands, paths, or APIs is a constitution defect (Article 16), because agents treat those files as ground truth. The check is: search markdown for tokens the change removed or renamed, read the hits, update the file if the claim is false. Rejected: a `core/` Python/Node doc-drift linter (the kit's portable core cannot take that dependency), failing the gate on every leftover token (changelogs and quotes of old names stay true), and file-age as a freshness signal (a year-old page can be accurate; a week-old page can already name a deleted flag). Procedures live in `sync-docs-from-diff`; review judges. Adopted from symbol-level drift checks in current agent-docs practice, not from calendar audits.
- 2026-10-04 - Blast radius and reversibility are a constitution defect (Article 17), because an agent that discovers extra callers or an irreversible migration otherwise keeps implementing. The check is: name radius and rollback in the plan; stop when reality is larger, or when a production/data/trust-boundary change has no reverse path the project already has. Rejected: requiring feature flags or canaries in every repository (AWS Well-Architected and Google SRE recommend them where the platform exists; this kit does not install one), and an LLM `Stop` hook that scores blast radius (same rejection as prompt-based stop hooks on 2026-10-02). The existing `pre-shell` hook remains the deterministic block for destructive commands. Procedures live in `assess-blast-radius`; review judges.
- 2026-10-04 - The mechanical diff review allows 80 files or 2500 changed lines (was 25 and 800). From 2026-10-02 through 2026-10-04, default-branch history records one size rejection that was not a bad change: Amigos #162, 39 files and 1707 lines, with the guard and the test gate already green. Amigos #170 (56 files, 943 lines) is the same shape. A docs archive (#167, at least 100 files) and a kit install (about 100 files, 2315 lines) stay over the new ceiling and still need `ai-large-diff-approved`. Rejected: raising only the 5-file plan step, because that is not the check that failed, and raising the ceiling to the kit-install size, because that diff is an exception. Actions run logs were not readable from this token, so the count is merged diffs and commit messages, not red job runs.
- 2026-10-04 - User-facing text in a language in scope is grammar-checked as the user sees it, including singular and plural when a dynamic value is combined with words (Article 15). Rejected: a regression-guard pattern for grammar, because agreement depends on the language and a script cannot tell a correct phrase from a broken one. Judged in `code-review`.
- 2026-10-03 - Cursor Projects fit the kit as a tool default, not as a MUST in the constitution. Rejected: naming Cursor in a MUST rule, requiring a Project per feature, or treating Project shared context as a source of truth. Adopted: Article 1 (uncommitted coordinator/shared context is scratch; durable lessons go through `capture-learning`), Article 3.4 (a coordinator is an orchestrator), Article 7 (the coordinator is not the reviewer), Article 13 (a subscription is not human approval), Article 14 (Projects are tool defaults). Usage is the installed `cursor-project` skill; human how-to lives in `docs/GROK-PLAYBOOK.md`. Tradeoff: Claude Code and Codex do not get a Projects UI, but they get the same articles when they plan-and-delegate, and they load `cursor-project` only when the description matches.
- 2026-10-03 - Enrichable product values and deploy-specific values live outside the source (Article 9). A literal stays allowed for a marked prototype or mock, and for a true program constant. Rejected: a regression-guard check on literals, because protocol fields, status codes, type discriminants, and test fixtures are literals on purpose and a script cannot tell them apart. Judged in `code-review`.
- 2026-10-02 - Enforcement by deterministic scripts (guard, verify, hooks, CI) rather than model-specific prompting. Rejected: per-model rule sets, because they drift and do not catch defects. Rules stay model-agnostic; model-specific advice lives in `docs/GROK-PLAYBOOK.md`.
- 2026-10-02 - Files are vendored into each repository by `install.sh` (pinned by `--kit-ref`), with CI drift detection. Rejected: git submodules (poorly supported by AI tools and easy to leave stale) and runtime downloads (break offline and make agent context depend on the network).
- 2026-10-02 - CI runs the guard from the central kit checkout, not the copy in the PR, so a PR cannot weaken its own guard.
- 2026-10-02 - Agent hooks are one bash script with a `--format` switch rather than one script per tool. All three tools accept the same blocking contract (exit code 2 for commands; Cursor `followup_message` vs Claude/Codex `decision: "block"` for stop). Rejected: prompt/agent-based stop hooks (not deterministic, and Cursor cloud agents run command hooks only) and `jq` (not installed on stock macOS). Tradeoff: payloads are matched with grep on the raw JSON, so a command that only mentions `--no-verify` in a string is also blocked.
- 2026-10-02 - Skills are installed to `.claude/skills/` because both Cursor and Claude Code load them from there; other tools get the list in `AGENTS.md`.
- 2026-10-02 - Installs go out by a rollout workflow in the kit that runs `install.sh` and opens one draft pull request per repository. The install branch is rebuilt from the default branch on every run. Rejected: committing installs through the GitHub API file by file (about 250 KB per repository, and the scripts must match byte for byte) and a hand-run loop. Tradeoffs: per-repository settings (stack, gate command, superseded paths) live in the kit's `rollout/`, and follow-up edits that need judgment go into separate pull requests, because the install branch is force-pushed.
- 2026-10-02 - Learnings flow back by harvest, not push. The kit's scheduled `harvest.yml` reads every repository that has `.ai/KIT_VERSION`, collects rules and skills that carry a `quality-kit:propose` marker, and opens one pull request per proposal. Rejected: a push workflow in every app (it needs a write token to the kit in every repository and a workflow change in each one) and a manual local script only (people forget to run it). Tradeoffs: proposals arrive up to a day late, and one token can read every app repository. Nothing merges automatically, because a kit change reaches every repository. One pull request per content hash, so closing a pull request rejects that version permanently.
